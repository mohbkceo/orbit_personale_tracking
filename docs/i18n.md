# Orbit localization

Orbit supports `en` and `ar`. New visitors start in Arabic. An existing account without a saved language remains in English. The canonical signed-in preference is `Setting.language`; the browser's `orbit-guest-language` value is only for visitors and for initializing a new account.

## Web strings

Add the same stable key to `client/src/i18n/locales/en.js` and `ar.js` in the relevant namespace, then render it with `useTranslation()` and a fully qualified key such as `t('tasks:title')`. Use i18next plural forms for counts. Keep user-entered names and descriptions as data rather than translating them. Translate labels for stored enum values at display time so API values stay stable. The key and interpolation checks are in `client/src/i18n/coverage.test.js`.

Use `client/src/utils/format.js` for displayed money, numbers, dates, and times. Keep stored amounts, timestamps, and currency codes unchanged. Test both document directions when changing navigation, overlays, or forms. Admin routes force English and LTR.

## Bot strings

Add each message key with the same interpolation variables in both dictionaries in `server/src/i18n/telegram.js`. Call `telegramText(settings, key, values)` using the recipient's settings, or pass the recipient's language. Interpolated values are HTML escaped; do not concatenate untrusted content into Telegram HTML. Keep `callback_data` identifiers unchanged and translate only displayed labels. Scheduled messages should resolve the recipient's language when delivered. Bot catalog checks are in `server/test/arabicI18n.test.js`.

## Synchronization

The web selector updates the UI immediately, then PATCHes `/settings`; a failed update rolls back. Login fetches `/settings` before showing the account UI. Registration passes the guest language to the server. The Telegram `/language` command writes the same Setting document. The web client refreshes settings when the tab becomes visible.
